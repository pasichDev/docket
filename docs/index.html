What it adds beyond "just a list"

Built for one person running more than one AI tool, in more than one project, at once.

Scoped to your project

Items file themselves under the project they were captured in. An agent in one repo never pulls two other projects' items into its context.

See what's open, on arrival

An optional Claude Code SessionStart hook injects what's open in this project — at most 7 items, under 120 tokens, nothing when there's nothing. It fails open: if docket is down, your session is unaffected.

Bridges, not replaces

Set sourceUrl and an item carries a link straight back to the GitLab issue, Notion page or Obsidian note it belongs to. Work lands here first, then graduates.

Private by default

The data file is AES-256-GCM encrypted on disk — nobody browsing your filesystem sees your tasks in plain text.

Local or self-hosted

Keep everything on this machine, or run one always-on Docket Server (Raspberry Pi, NAS, VPS) and pair every device to it. See how ↓

Two ways to run it

Local Mode is the default and needs nothing below. Self-hosted Mode is opt-in, for an always-on machine you control.

Every device is a thin, per-device-authenticated forwarder — there's no local writable copy, and the list stays up even when every laptop is off. See how to set it up ↓

Claims are advisory in Local Mode (they can be taken over, and across P2P sync they can be up to one 15-second pull interval stale) and atomic in Self-hosted Mode (a racing claim gets a 409, decided by one authority). P2P sync is deprecated in v3.0 for exactly that reason — it still works, and nothing is removed, but Self-hosted is the supported multi-machine path.

Installation guide

Five minutes, no prior MCP experience needed.

1

Register the server

Open a terminal and run:

claude mcp add docket -- npx -y @pasichdev/docket
2

Restart Claude Code

Close and reopen it, or start a new session, so it picks up the new server.

3

Try it

Ask Claude something like "add a todo: buy milk". If it uses the tool and confirms, you're set.

4

Open the web UI

Go to http://localhost:8787 — it started itself the moment step 3 ran.

5
Optional

See what's open when a session starts

Installs a Claude Code SessionStart hook (merged into your existing .claude/settings.json, never overwriting it), plus the field reference skill. The hook runs a command, so it wants docket on your PATH — it works without, pinned to this install, and says so:

npm install -g @pasichdev/docket
docket hook install
docket hook doctor

/plugin marketplace add pasichDev/docket
/plugin install docket@docket

Want an always-on shared workspace?

Run one Docket Server on a Raspberry Pi, mini PC, NAS, home server, or VPS — every device you pair with it shares the same authoritative workspace, even when your laptop is off. This is the actual CLI output, not a mockup.

1

Start the server

On the always-on machine:

$ npm install -g @pasichdev/docket
$ docket serve --host 0.0.0.0
docket server ready
API:  http://0.0.0.0:8788/api/v1
Data: ~/.docket (default)
Auth: per-device signed requests — no client can call the API until it's paired.
      Pair a new device from THIS machine with: docket devices pair
2

Pair a device

From the client machine — this waits for explicit approval on the server, never silent:

$ docket pair https://docket.home.example
✓ Server reachable
✓ docket server v2.3.0
✓ Protocol compatible

Confirmation code: 7XP-KR4
Check that the SAME code appears next to this request on the server (docket devices pending) before approving it there.

Waiting for approval...
✓ Device paired
✓ Connection authenticated
✓ Remote workspace ready
3

Check on it, any time

$ docket status
Mode: remote
Server: https://docket.home.example
Status: connected
Latency: 18 ms
Server version: 2.3.0
Device: andrii-desktop
Device authorization: active
4

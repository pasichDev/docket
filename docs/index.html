Why not just a text file

What it adds beyond "just a list"

Built for one person running more than one AI tool, in more than one project, at once.

Scoped to your project

Items file themselves under the project they were captured in. An agent in one repo never pulls two other projects' items into its context.

See what's open, on arrival

An optional Claude Code SessionStart hook injects what's open in this project — at most 7 items, under 120 tokens, nothing when there's nothing. It fails open: if docket is down, your session is unaffected.

Bridges, not replaces

Set sourceUrl and an item carries a link straight back to the GitLab issue, Notion page or Obsidian note it belongs to. Work lands here first, then graduates.

Private by default

The store is AES-256-GCM encrypted on disk. Nothing leaves your machine unless you pair it with a server you run — there is no account, and no telemetry.

Local or self-hosted

Keep everything on this machine, or run one always-on Docket Server (Raspberry Pi, NAS, VPS) and pair every device to it. See how ↓

Your data stays yours

One command writes an encrypted, portable backup of the whole workspace — identity, keys and all — and one restores it on another machine. Plain docket export gives you JSON or Markdown.

Getting started

Installation guide

Five minutes, no prior MCP experience needed.

1

Register the server

Open a terminal and run:

claude mcp add docket -- npx -y @pasichdev/docket

Using something other than Claude Code? Point it at the same command — the server speaks plain MCP over stdio.

2

Restart Claude Code

Close and reopen it, or start a new session, so it picks up the new server.

3

Try it

Ask Claude something like "add a todo: buy milk". If it uses the tool and confirms, you're set.

4

Open the web UI

Go to http://localhost:8787 — it started itself the moment step 3 ran. Check on it from a terminal any time:

$ docket status
Mode: local
Store: ~/.docket (from the default location)
Web: http://localhost:8787
Workspace: github.com/acme/backend via git-remote at ~/work/backend
Sessions: 2 open
Peers: 0
5
Optional

See what's open when a session starts

Installs a Claude Code SessionStart hook (merged into your existing .claude/settings.json, never overwriting it), plus the field reference skill. The hook runs a command, so it wants docket on your PATH — it works without, pinned to this install, and says so:

npm install -g @pasichdev/docket
docket hook install
docket hook doctor

/plugin marketplace add pasichDev/docket
/plugin install docket@docket

Optional

Want an always-on shared workspace?

Run one Docket Server on a Raspberry Pi, mini PC, NAS, home server, or VPS — every device you pair with it shares the same authoritative workspace, even when your laptop is off. Every transcript below is real output, not a mockup.

1

Start the server

On the always-on machine:

$ npm install -g @pasichdev/docket
$ docket serve --host 0.0.0.0
docket server ready
API:  http://0.0.0.0:8788/api/v1
Data: ~/.docket
Auth: per-device signed requests (RFC §14) — no client can call the API until it's paired.
      Pair a new device from THIS machine with: docket devices pair

Prefer containers? docker compose up -d from the repo brings up the same thing, with a healthcheck and a named volume.

2

Mint a pairing code, on the server

$ docket devices pair
4PYD2F
Expires in 5 minute(s).
Give this code to the device being paired (it runs `docket pair <this server's URL>`), then approve it here:
  docket devices pending
  docket devices approve <requestId>
3

Pair the device

From the client machine. It waits for explicit approval on the server — never silent, and the confirmation code has to match on both ends:

$ docket pair https://docket.home.example
Pairing code (from `docket devices pair` on the server): 4PYD2F
✓ Server reachable
✓ docket server v3.0.0
✓ Protocol compatible

Confirmation code: 096674
Check that the SAME code appears next to this request on the server (docket devices pending) before approving it there.

Waiting for approval...
✓ Device paired
✓ Connection authenticated
✓ Remote workspace ready
4

Check on it, any time

$ docket status
Mode: remote
Server: https://docket.home.example
Status: connected
Latency: 27 ms
Server version: 3.0.0
Device: andrii-desktop
Device authorization: active
5

Use Claude/Codex/Cursor exactly like Local Mode

Same MCP config, same tools — only where the data lives changed. The mode is recorded once, centrally, so switching back later takes one command and no config editing:

$ docket backend use https://docket.home.example   # move this device to the server
$ docket backend localize                          # …and bring the workspace back later

How much you can trust it

It holds your only copy, so it is built like it

A todo list is not important — until it is the only record of what you were doing. Every write goes to disk atomically and durably, is checked against the exact bytes it read, and refuses rather than guesses when two processes disagree. 3.0 went through a full release-readiness audit before it shipped; all 27 blockers are closed, each with a regression test verified to fail against the code it replaced.
